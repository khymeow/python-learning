### 目前已练习的主要算法思路

以下记录已经写过或练习过的思路，仍需通过不看答案的独立复现和解释代码来巩固。

**1. 前缀和**

通过累加得到当前位置的累计结果。代表题目：LeetCode 1480。

**2. 哈希表与集合**

使用字典完成计数和快速查询，使用集合完成去重与成员判断。代表题目：LeetCode 1、1207、217。

其中，两数之和从最初的双重循环解法，优化为使用字典查找补数的平均 O(n) 解法；第 217 题使用集合记录出现过的数字，发现重复时提前返回。

**3. 双指针**

利用两个索引控制遍历范围。代表题目：LeetCode 11、167、283。

第 11 题从 O(n²) 双重循环优化为 O(n) 双指针；第 167 题利用数组有序性移动左右指针；第 283 题通过同向双指针原地调整数组，时间 O(n)、额外空间 O(1)。

**4. 栈的基础应用**

LeetCode 20「有效的括号」练习了后进先出与字典匹配。当前已完成基础应用，**仍需巩固**；单调栈等进阶内容尚未系统学习。

**5. 队列与双端队列**

在 LeetCode 933 和后续 BFS 题中使用 `collections.deque`，练习了初始化、`append()`、`popleft()`、队列中的元组坐标，以及队列与集合的配合。已比较列表 `pop(0)` 与 `deque.popleft()` 的操作复杂度，并接触滑动窗口的均摊分析。

**6. 图、邻接表与 BFS（基础专题已完成，仍需巩固）**

- **1971「寻找图中是否存在路径」**：通过邻接表表示无向图，用 BFS 判断节点可达性。曾遇到邻接表初始化、双向边记录、队列初始化及不同数据结构组合使用的问题。
- **752「打开转盘锁」**：单源 BFS 处理最短步数，在状态空间中生成相邻状态，结合死亡状态集合、`visited` 和队列。练习了状态建模、元组与队列操作。
- **994「腐烂的橘子」**：多源 BFS，所有初始腐烂橘子同时入队，记录传播时间；使用 `fresh` 计数和原地状态标记，避免反复扫描。
- **200「岛屿数量」**：使用 BFS 统计二维网格中的连通区域。初版独立编写、根据提示修正错误；优化时把 BFS 嵌入单次网格遍历，去掉 `onenum`、`found` 和嵌套 `break`，将最坏 O(kmn) 的重复寻岛扫描优化为 O(mn)。最终优化结构经过讲解并由 AI 辅助整理。

第 200 题重点错误复盘：`'1'` 与整数 `1` 不能混用；`queue.append((i, j))` 需要把坐标作为一个元组；`set()` 创建空集合，`visited.add((i, j))` 记录完整坐标；内层 `break` 不会退出全部外层循环。

这四道题分别覆盖**可达性、最短路径、多源传播、连通区域计数**。基础专题已完成，但需继续独立复现、分析边界条件和优化过程。

**7. DFS 与递归（已完成两道基础练习，正在巩固）**

**[733「图像渲染」](https://leetcode.cn/problems/flood-fill/)**

先使用已掌握的 `deque` 完成 BFS 版本；随后学习递归的进入与返回顺序，用嵌套函数 `dfs(i, j)` 完成递归 DFS 版本，已保存到 `leetcode_733.py`。这题主要练习：

- 递归调用先深入、完成后逐层返回；通过调用栈保存尚未完成的方向遍历。
- 保存原始颜色 `oc`；原颜色等于新颜色时直接返回。
- 递归进入格子后立即改成新颜色，只继续访问原颜色相同的上下左右邻居。
- 初次写递归 DFS 时遗漏 `image[ni][nj] == oc`，会错误地修改不同颜色的像素；经检查后修正。
- 认识到当 `oc != color` 时，**修改后的颜色本身可以表示“已访问”**，因此本题最终 DFS 代码不需要额外 `visited` 集合。

这道题练习的是**执行型递归**：函数负责修改符合条件的像素，不需要汇总返回值。题解保留了从 BFS 迁移到 DFS 的真实学习过程。

**[695「岛屿的最大面积」](https://leetcode.cn/problems/max-area-of-island/)**

在第 733 题的基础上独立尝试递归 DFS，最终代码在调试指导后修正并保存到 `leetcode_695.py`。本题使用外层双重 `for` 寻找未访问岛屿、`visited` 记录位置；递归函数 `dfs(i, j)` 以 `num = 1` 表示当前陆地的面积，利用 **`num += dfs(ni, nj)`** 累加相邻连通区域的面积，最终使用 `maxarea = max(maxarea, dfs(i, j))` 更新最大面积。

实际遇到并修正的问题：

- 沿用上一题变量名 `image`，本题应使用 `grid`。
- 外层最大面积变量未初始化；改用 `maxarea = 0`，理解内外函数局部变量的区别。
- 最初只执行 `dfs(ni, nj)` 而忽略递归返回值，导致更深层的面积没有累加；改为 `num += dfs(ni, nj)`。
- 外层寻找新岛屿时遗漏 `not in visited`，可能对已处理陆地重复启动 DFS。
- 修正过一组测试的错误预期：`[[1,0,0],[1,0,1],[1,0,1]]` 的最大面积是 **3**，不是 2。

这道题练习的是**计算型递归**：函数将子递归计算得到的面积逐层返回并汇总。

**DFS 阶段当前结论：** 已能够写出基础网格递归 DFS，理解访问标记、终止条件与返回值累加；尚需独立复现并逐步掌握非网格 DFS、显式栈和更复杂的递归/回溯问题。Python 递归存在深度限制，733 和 695 的递归代码在很大且连通路径很长的输入下可能触发 `RecursionError`；理论时间复杂度 O(mn) 不代表所有极端输入都能用递归版本运行成功。

**8. 链表基础与迭代反转**

已练习 `ListNode` 节点、`val` 与 `next`、`head` 与遍历引用 `current` 的区别、链表遍历与数值求和、中间插入节点、删除中间节点及头尾节点、只给 `head` 时寻找倒数第二个节点，以及空链表和单节点边界。

已完成 [LeetCode 206「反转链表」](https://leetcode.cn/problems/reverse-linked-list/)，保留迭代解法：`prev` 表示已反转部分的头节点，`current` 表示待处理节点，`next_node` 保存原有后继。每轮先保存后继，再反转 `current.next`，最后移动 `prev` 与 `current`，返回新头节点 `prev`。时间复杂度 O(n)，额外空间复杂度 O(1)。

真实复盘：最初让尾节点直接指向头节点只会形成环；修改 `.next` 前必须保存后继，不能依赖反复叠加 `.next.next.next` 寻找节点。某版 `while next_node is not None` 漏处理尾节点；使用 `while current is not None` 并在每轮开头保存后继，才能统一处理全部节点。`while` 在每轮开始前检查条件，不能在 `current` 可能为 `None` 时提前访问 `.next`。曾在循环末尾有条件地更新后继，导致尾部重复处理、可能成环；这些问题均已在最终版本修正。

最终版本在多次独立尝试和针对性讲解后完成，已理解变量移动和终止条件，仍需间隔复现检验熟练程度。当前状态：**链表基础操作和迭代反转已完成入门，仍需独立复现和继续练习。**

## 六、如何运行

### 环境要求

- Python 3（建议使用 Python 3.9 或更新版本，以支持部分题解中的 `list[list[int]]` 注解）。
- Git（用于版本管理）。

当前题解主要使用 Python 标准库，无需额外安装第三方依赖。

### 克隆仓库

```bash
git clone https://github.com/khymeow/python-learning.git
cd python-learning
```

### 运行题解

例如：

```bash
python leetcode_200.py
python leetcode_733.py
python leetcode_695.py
python leetcode_206.py
```

其他题目也可以使用 `python leetcode_题号.py` 独立运行；具体测试与输出以对应文件内容为准。

## 七、学习与代码提交方式

本仓库坚持**独立解题为主、AI 辅助工程管理**的原则。

学习流程：

1. 理解 Python 知识点或算法题目。
2. 独立分析问题并编写第一版代码。
3. 运行测试并检查边界条件。
4. 分析时间复杂度与空间复杂度。
5. 尝试优化算法，理解原理。
6. 在适当时候完成 LeetCode 在线提交；仓库中的题解不代表已完成在线提交。
7. 整理最终代码和实际错误记录，更新 GitHub 与 README。

遇到困难可以借助讲解和调试指导，但题目完成后仍需复盘错误、不看完整答案重写，并检查是否能解释实现原理。

### Codex 与其他辅助工具的职责

- 整理**已有**题解，保留用户提供的算法结构。
- 根据真实过程补充题意、必要注释、复杂度和错误复盘。
- 运行测试，维护代码文件，协助 Git 提交和推送。
- 按实际文件数量及确认的学习进度维护 README。
- 不在未要求的情况下代替独立解题，不把计划中的知识写成已掌握。

具体规则见 [AGENTS.md](AGENTS.md)。
